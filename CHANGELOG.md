# Changelog

## Unreleased

- iOS: the IPA attached to a release `vX.Y.Z` now shows that version. `.github/workflows/ios.yml` passes `MARKETING_VERSION` (the tag without `v`) and `CURRENT_PROJECT_VERSION` (run number + 100) to xcodebuild for tag builds, and fails the job if the built app's `CFBundleShortVersionString` differs from the tag (before the IPA is zipped or attached); `latest` and PR builds keep `ios/project.yml`, now `1.3.25` (build 29). Before, the IPAs of v1.3.23-v1.3.25 all said 1.3.22 because the number was bumped by hand.
- Home screen, "Chi phí": Codex spend now shows up. The box reads every Codex home (`~/.codex`, `~/.codex-*`, `~/.codex-accounts/*`, each real folder once), not only one, so the Astra runs of every account are counted. The gpt-6 models (astra, sol, luna, terra, 6.1, cyber, rosalind, astra-law) now have prices, cache writes are priced, and a request above 272,000 input tokens is billed at the higher long-context rate (2x input and cache, 1.5x output) for the models whose OpenAI page states it.
- Box guard for workflow (`.github/`) changes, default-deny: only a repo whose GitHub slug is listed in `~/.config/fcode/no-secret-repos` (the owner confirmed its Actions repository secrets page is empty; no file, an unreadable or non-regular one, or one holding a NUL byte = no repo) may change `.github/` from the box. The box pre-push hook (`box/fcode-add.sh` `hook_text`, still blocking main/master) refuses every other pushed branch or tag whose `.github/` tree equals neither the remote ref's current value nor origin's default branch (so `git merge origin/main` and a rebase push); "no `.github/`" is never a base, so removing an existing `.github/` is refused too and a new ref with neither base (a `--single-branch` clone, an empty repo, a default branch other than main/master with no `origin/HEAD`) is refused with its own message naming `git remote set-head origin --auto`, which `fcode add` (after the clone; `R HOOK_OK|HOOK_EXISTS HEAD_OK|HEAD_FAIL`) and `fcode-hooks` (per project, `HOOK_OK|HOOK_EXISTS <name> HEAD_OK|HEAD_FAIL`) now run, best effort; only a commit whose whole tree is empty (`fcode add`'s probes) always pushes; an owner-approved file `~/.config/fcode/guard-allow/<owner>__<repo>__<sha>` lets that commit through; the refusal names the rebase/merge for a branch older than `origin/main`. New `box/gh-guard.sh`, installed as `~/.local/bin/gh` ahead of `/usr/bin/gh`, refuses (exit 65): `gh alias`, `gh extension` and any first word that is not a full built-in gh command; `gh pr merge` / `gh api` calls with unknown flags (parsed like pflag; `--help` changes nothing; pr-merge refusals name `gh help pr merge`); in an unlisted repo, `gh pr merge` with an auto flag or of a PR whose REST file list (new and old names) touches `.github/` or is incomplete — the owner merges those on GitHub; everywhere, every `gh api graphql` and every non-GET `gh api`. Other merges in unlisted repos run pinned to the inspected head (`--match-head-commit`). No workflow content is read. New `box/fcode-hooks.sh` (`~/.local/bin/fcode-hooks`, run by `install.sh`) puts the current hook into every project already added (a relative `core.hooksPath` is read from the project); `fcode-add.sh --hook-text` prints it. Not a security boundary; see docs/HUONG-DAN.md, "Sửa workflow từ box". `box/agents-git.md`: the new rule, and shopee-dashboard is deployed by the generic gate (its Actions deploy workflow was retired).
